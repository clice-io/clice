# 索引

超出已打开文件范围的答案——查找引用、调用层次结构与类型层次结构、工作区符号、重命名，以及在尚未编译的文件上的悬停或导航——都来自 clice 为项目建立的索引。本页介绍索引包含哪些内容，以及如何缩短大型项目首次建立索引的时间。

## 索引包含哪些内容

服务器启动时，后台索引会编译项目中的每个翻译单元：编译数据库中的每个文件、规则的 `default_command` 覆盖的源文件，以及之前打开过、却没有任何数据库列出的文件。它会等你空闲 `background_delay_ms` 之后才开始，在后台 worker 上运行，并为你正在处理的文件的请求让路。头文件通过包含它的翻译单元建立索引，每种包含方式各索引一次，因此被不同源文件以不同方式编译的头文件，能针对其中每个上下文给出答案。

索引为每个文件记录它的声明、定义和引用，谁调用了谁，谁派生自谁，以及各翻译单元产生的模板实例化。在函数体内部，索引记录函数体用到的名字，除非 `index_function_body` 把该文件的函数体排除在外：默认情况下，系统头文件（标准库、`-isystem` 目录）的函数体会被排除，在那里编写的模板的实例化也一样。系统头文件的其余部分——声明、类型、模板——都会建立索引。

索引保存在缓存目录中。下一次启动的服务器或下一次 `clice index` 运行会加载它，只重新编译此后文件发生了变化的翻译单元。`clice index` 在命令行中构建或更新索引；如果有服务器正在服务该项目，它会请那个服务器来完成。

## 加快首次索引

大型项目的首次索引要把每个翻译单元都编译一遍。有三种办法可以缩短它：

- **更多 worker。** `[workers] background` 是同时编译的翻译单元数量：默认为机器物理核心数的一半。如果机器核心多、内存也有富余，就调高它。
- **更少的翻译单元。** 设置了 `background_index = false` 的规则，会让它匹配的文件不作为独立的翻译单元编译：适用于你不会在其中导航的测试、示例、基准测试或生成的源文件。它们包含的头文件仍会通过包含它的其他翻译单元建立索引。
- **跳过函数体。** 设置了 `skip_function_body = true` 的规则，会让除文件自身的编译之外的每次编译都跳过它所匹配文件中的函数体（包括模板），编辑器和后台索引都是如此。把它用在第三方代码上：项目中的翻译单元就只解析它们所包含的库的声明，它们导入的库模块在构建时也会跳过函数体。转发实参的函数模板（如 `std::make_unique`）仍会解析，编译器需要的 `constexpr` 函数和返回 `auto` 的函数也一样。

```toml
[[rules]]
patterns = ["third_party/**", "external/**"]
skip_function_body = true
background_index = false
lint = false
format = false

[[rules]]
patterns = ["benchmarks/**"]
background_index = false

[workers]
background = 16
```

跳过的代价：这些函数体中的错误不会报告，你的代码实例化其模板时引发的错误也不会报告，函数体用到的名字也不会建立索引——查找引用和调用层次结构止步于它们的声明。`skip_function_body = false` 在所有地方关闭跳过，包括编辑器自身的编译：默认情况下，编辑器跳过打开文件顶部所包含头文件中的函数体，由后台索引解析它们，并把在其中发现的问题报告在该文件上。

## 库的内部实现

要在标准库或其他系统库内部导航——查找库中某个函数的调用者，或其模板的实例化——就让一条规则为它的函数体建立索引：

```toml
[[rules]]
patterns = ["/usr/include/c++/**"]
index_function_body = true
```

索引每多记录一个函数体就会变大一些，因此最好只对你会阅读的库这样做。
