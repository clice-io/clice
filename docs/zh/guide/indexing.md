# 索引

超出已打开文件范围的响应——查找引用、调用层次结构与类型层次结构、工作区符号、重命名，以及在尚未编译的文件上的悬停或代码导航——都来自 clice 为项目建立的索引。本页说明索引包含哪些内容，以及如何缩短大型项目首次建立索引的时间。

## 索引包含的内容

服务器启动时，后台索引会编译项目中已保存索引尚未记录为最新的每个翻译单元：编译数据库中的每个文件、规则的 `default_command` 覆盖的源文件，以及此前打开过但未列在任何编译数据库中的文件。任务入队并经过 `[workers] background_delay_ms` 后后台索引开始运行，使用后台 worker，并为你正在编辑的文件上的请求让路。头文件通过包含它的翻译单元建立索引，每种包含方式各索引一次，因此被不同源文件以不同方式编译的头文件，能针对其中每个上下文给出结果。

索引为每个文件记录其声明、定义和引用、调用关系、继承关系，以及各翻译单元产生的模板实例化。在函数体内部，索引会记录函数体用到的名称，除非 `index_function_body` 将该文件的函数体排除在外：默认情况下，系统头文件（标准库、`-isystem` 目录）中的函数体不建立索引，写在其中的模板所产生的实例化也一样。系统头文件的其余部分——声明、类型和模板本身——仍会建立索引。

索引保存在缓存目录中，构建期间每五分钟保存一次，运行结束时也会保存。下次启动的服务器或 `clice index` 运行会加载这份索引，只重新编译此后文件发生变化的翻译单元。`clice index` 可在命令行中构建或更新索引；若同一版本 clice 的服务器正在服务该项目，它会请求该服务器代为完成。

同一时间只有一个进程写入项目的索引。针对同一项目启动的第二个服务器（例如第二个编辑器窗口）最多等待五秒，让第一个进程释放索引，这足以让重启前旧服务器的进程完成保存；若超时后索引仍被占用，第二个服务器不会服务该项目的任何内容，并指明占用索引的进程。

## 加快首次索引

大型项目的首次索引需要把每个翻译单元编译一遍；这是一次性开销，后续启动只编译有变化的部分，中途中断的运行也会从中断处继续。会话日志记录了耗时分布：每个翻译单元一行，写明其耗时；环境变量中设置 `CLICE_PERF=1` 时，每个翻译单元还会额外输出一行 `[perf:index]`，将耗时拆分为建索引和合并两段，整次运行结束时也汇总一行。有四件事可以缩短首次索引时间：

- **更多 worker。** `[workers] background` 控制服务器同时编译的翻译单元数量：默认为机器物理核心数的一半，至少为 2，且不超过 `[workers] max`（默认为全部核心数）。如果机器核心多且内存充裕，可以调高它。`clice index` 同时编译 `--jobs` 个翻译单元，默认等于机器的逻辑 CPU 数。
- **充足的内存。** 只有机器剩余内存足够时才会启动新的翻译单元编译，内存吃紧时最新启动的任务会被中止，因此在内存不足的机器上增加 worker 并无帮助；后台任务因等待内存而暂停时会写入日志。如果某个翻译单元连单独运行都放不下，`clice index` 会点出它的名字以及其 worker 达到的内存占用。
- **更少的翻译单元。** 设有 `background_index = false` 的规则会让匹配的文件不作为独立翻译单元编译，适合你不会在其中导航的测试、示例、基准测试或生成源文件。它们包含的头文件仍会通过包含该头文件的其他翻译单元建立索引；模块单元或生成预编译头文件的单元，在其他翻译单元需要其模块或预编译头文件时仍会编译。有些构建生成器会把头文件也写进编译数据库，使每个头文件在包含它的源文件之外又成为独立的翻译单元；针对 `**/*.h` 设置 `background_index = false` 的规则即可排除它们。
- **跳过函数体。** 设有 `skip_function_body = true` 的规则会让除文件自身编译之外的每次编译都跳过匹配文件中的函数体（包括模板），编辑器和后台索引皆然。将其用于第三方代码后，项目中的翻译单元只解析所包含库的声明，导入的第三方库模块在构建时也会跳过函数体。转发实参的函数模板（如 `std::make_unique`）仍会解析，`constexpr` 函数、`consteval` 函数以及返回 `auto` 的函数也一样。

```toml
[[rules]]
patterns = ["third_party/**", "external/**"]
skip_function_body = true
background_index = false
lint = false
format = false

[[rules]]
patterns = ["benchmarks/**", "**/*.h"]
background_index = false

[workers]
background = 16
```

跳过函数体的代价：这些函数体内部的错误不会报告，你的代码实例化其模板时触发的错误也不会报告，函数体内部使用的名称同样不会建立索引——查找引用和调用层次结构会止步于它们的声明。`skip_function_body = false` 会在所有地方关闭跳过，包括编辑器自身的编译：默认情况下，编辑器会跳过已打开文件顶部所包含头文件中的函数体，改由后台索引解析它们，并把在其中发现的问题报告在按自身数据库条目编译的文件上。

## 库的内部实现

要在标准库或其他系统库内部导航——查找库内某个函数的调用方，或其模板的各处实例化——可通过规则为它的函数体建立索引：

```toml
[[rules]]
patterns = ["/usr/include/c++/**"]
index_function_body = true
```

每多记录一个函数体，索引体积都会相应增大，因此最好只对你会阅读的库开启。
