# Toolchain Changelog

Pitfalls met while building and consuming the prebuilt LLVM packages: the package
definition (`scripts/build-llvm.py`, `build-llvm.yml`, the clice-llvm patches) and
the consumer side (`cmake/llvm.cmake`). `llvm-changelog.md` covers clang API changes;
this file covers everything around them. Every entry: what you see, why, what we do,
how to check it before spending CI time. Append to it with every toolchain change.

## 2026-09: libc++ inside the package, clang 23.1.1 (LLVM 22.1.8 → 22.1.8+r1)

The package started shipping its own static libc++ and was rebuilt with the pixi
clang 23.1.1; the LLVM libraries stayed at 22.1.8. Four CI rounds were needed. What
follows is every reason why.

### Package definition

| Building libc++ through `LLVM_ENABLE_RUNTIMES` would need a clang executable.                                                           | The bootstrapping runtimes build compiles libc++ with the clang built in the same tree; a package with no code-generation target has no usable clang.                                                                                                                                    | Two configures into one prefix: `runtimes/` first with the pixi clang, then `llvm/` with `-nostdinc++ -isystem <prefix>/include/c++/v1` and `-stdlib=libc++ -L<prefix>/lib`.                                          | `--configure-only` runs both.                                                                                                                                             |
| `libcxx/src/.../from_chars_floating_point.h: 'shared/fp_bits.h' file not found` when building libc++ from a partial source tree.        | libc++ 23 includes LLVM libc's `libc/shared/` headers.                                                                                                                                                                                                                                   | Always give `--runtimes-src` a full llvm-project checkout (CI clones one); a hand-copied tree must include `libc/`.                                                                                                   | Only local shortcuts hit this.                                                                                                                                            |
| `install(EXPORT "ClangTargets" ...) includes target "X" which requires target "Y" that is not in any export set` at the LLVM configure. | `COMPONENTS` is an explicit list; `Y` is a transitive dependency that is missing from it. This is the guard that makes the list safe: an incomplete list cannot configure.                                                                                                               | Add `Y` (found this way: `clangDynamicASTMatchers`, `clangQuery`, `LLVMLineEditor` through the tidy Custom module, `LLVMDemangle` through `LLVMSupport`).                                                             | The local `--configure-only` run.                                                                                                                                         |
| `Specified distribution component 'X' doesn't have an install target`.                                                                  | A `COMPONENTS` entry names a library the new LLVM no longer has.                                                                                                                                                                                                                         | Remove it.                                                                                                                                                                                                            | Same run.                                                                                                                                                                 |
| clice's `cmake/clang-tidy-config.h` says analyzer off, the package's `clangTidy` was built with it on.                                  | `clang-tidy-headers` installs `*.h` from the source directory only; the generated `clang-tidy-config.h` never ships, so clice carries its own and it must agree with the package.                                                                                                        | `CLANG_TIDY_ENABLE_STATIC_ANALYZER=OFF`, `CLANG_TIDY_ENABLE_QUERY_BASED_CUSTOM_CHECKS=OFF` in the LLVM configure; `clangTidyMPIModule` and `clangTidyCustomModule` then do not exist and must not be listed anywhere. | Export-set errors if the list disagrees.                                                                                                                                  |
| `LLVM_DEFAULT_TARGET_TRIPLE` comes out empty; a clang without `--target` has no target.                                                 | With `LLVM_TARGETS_TO_BUILD` empty there is no native target, and LLVM derives the default triple from it.                                                                                                                                                                               | The script passes the runtimes configure's `LLVM_DEFAULT_TARGET_TRIPLE` (normalized by the compiler, cached there; `LLVM_HOST_TRIPLE` is not cached) to the LLVM configure.                                           | `grep LLVM_DEFAULT_TARGET_TRIPLE build/llvm/include/llvm/Config/llvm-config.h`.                                                                                           |
| Does dropping the backends change the frontend?                                                                                         | Only three frontend spots consult the target registry (MS `__asm` blocks, target inference from a `<triple>-clang` program name, `clang -v`), and all need a _registered_ target. clice never calls `LLVMInitialize*`; every `LLVMX86*` archive was already pruned from the old package. | Nothing; behavior is identical.                                                                                                                                                                                       | `grep -rn TargetRegistry clang/lib` for a new release.                                                                                                                    |
| aarch64 cross leg: `x86_64-conda-linux-gnu-ld: unrecognised emulation mode: aarch64linux` in the runtimes compiler test.                | `-DCMAKE_C_FLAGS`/`-DCMAKE_EXE_LINKER_FLAGS` on the command line replace the toolchain file's `*_INIT` values, so its `-fuse-ld=lld` (and `--no-default-config` on Darwin) never reached the configure; `LLVM_USE_LINKER` only acts after `project()`.                                   | The script names `-fuse-ld=lld` (and `--no-default-config` on Darwin) itself in both passes.                                                                                                                          | The cross env exists locally: `pixi run -e cross-linux-arm64 ... --target-triple aarch64-unknown-linux-gnu --configure-only` (builds the native tablegen tools, minutes). |
| The workflow passes `--runtimes-src=.runtimes`; the script looked for `.llvm/.runtimes`.                                                | The script `os.chdir`s into the LLVM tree before resolving the second path.                                                                                                                                                                                                              | Both paths are resolved before the chdir.                                                                                                                                                                             | Reproduce CI's call shape: a scratch dir with `.llvm` and `.runtimes` symlinks, relative arguments.                                                                       |
| `ninja -n` counts 4 compiles for a 5804-step plan.                                                                                      | Dry-run output is elided.                                                                                                                                                                                                                                                                | `ninja -t commands install-distribution` and count `-c` lines (`print_build_plan`).                                                                                                                                   |                                                                                                                                                                           |

### Windows

| Symptom                                                                                                                                                                         | Cause                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | What we do                                                                                                                                                                                                                                                                                              | How to check                                                                                                                                                              |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `clang-cl: unknown argument ignored: -nostdinc++`.                                                                                                                              | clang-cl has no such option, and for MSVC targets it would do nothing anyway: the MSVC STL headers live in the `INCLUDE` directories together with the C runtime headers.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | `/clang:-isystem<prefix>/include/c++/v1`; `-isystem` is searched before the `INCLUDE` directories, which shadows the MSVC STL. libc++ built static-only enters the upstream `clang-cl-static` configuration (`_LIBCPP_DISABLE_VISIBILITY_ANNOTATIONS`, `#pragma comment(lib, "libc++.lib")` auto-link). | The LLVM configure's compiler checks compile against libc++.                                                                                                              |
| `lld-link: error: /failifmismatch: mismatch detected for '_CRT_STDIO_ISO_WIDE_SPECIFIERS': LLVMTableGen.lib(Main.cpp.obj) has value 0, libc++.lib(string.cpp.obj) has value 1`. | Upstream builds libc++ with `_CRT_STDIO_ISO_WIDE_SPECIFIERS`, hard-coded since 2017 with no knob and no upstream issue. The macro changes what `%s`/`%c`/`%[` mean in the wide printf/scanf family (ISO: `%s` is `char*`; MS default: `wchar_t*`). The mode is per process: the UCRT keeps one options word (`__local_stdio_printf_options`), and any object compiled with the ISO define auto-links (`#pragma comment(lib)` + `/include:`) the initializer that switches the whole image, hence the `detect_mismatch` records. Defining the macro everywhere would flip libuv, whose Windows directory scanning (`fs.c`) and fs-event code pass `WCHAR*` to `%s`; suppressing the check would hide a real per-image flip. | clice-llvm patch `patches/23.1.1/0001`: build libc++ with `_CRT_STDIO_ARBITRARY_WIDE_SPECIFIERS`, the define the UCRT documents for static libraries that use no such specifiers. libc++'s only wide printf use is number formatting in `to_wstring`. Consumers need nothing.                           | Probe: `_snwprintf(buf, n, L"%s\\x", L"dir")` linked against the new `libc++.lib` prints `dir\x` by default and `d\x` with `/D_CRT_STDIO_ISO_WIDE_SPECIFIERS`; both link. |
| With libc++ 22: `LNK2005: std::exception_ptr::exception_ptr(exception_ptr const&) already defined in libcpmt.lib(future.obj)` (and `~exception_ptr`, `rethrow_exception`).      | libc++ 22 implements `exception_ptr` on the vcruntime ABI by calling `__ExceptionPtr*` from the MSVC STL while defining the member functions itself; the STL's `future.obj` defines the same members. Upstream [#158562](https://github.com/llvm/llvm-project/issues/158562); fixed by libc++ carrying its own implementation in [#94977](https://github.com/llvm/llvm-project/pull/94977), which is in 23.1.1.                                                                                                                                                                                                                                                                                                            | The package's libc++ is built from the pixi clang's release (`--runtimes-src`, 23.1.1), not from the LLVM being packaged. This is also the principled rule: libc++ follows the compiler.                                                                                                                | `probe2.cpp` (`std::set_new_handler`, `std::current_exception`, `std::to_string`) linked against the fresh `libc++.lib`.                                                  |
| `unresolved external symbol std::set_new_handler` with libc++ 23.                                                                                                               | On the vcruntime ABI libc++ leaves `set_new_handler` to the MSVC STL (`libcpmt.lib(stdhndlr.obj)`), and nothing auto-links libcpmt once the STL headers are shadowed. Upstream's tests link `-llibcpmt`; [#209663](https://github.com/llvm/llvm-project/pull/209663) (LLVM 24) only removes libcpmt from libc++'s own shared-library link line and does not help.                                                                                                                                                                                                                                                                                                                                                          | `/DEFAULTLIB:libc++.lib /DEFAULTLIB:libcpmt.lib` in that order, in the LLVM build and in `cmake/llvm.cmake` (`-Wl,` prefixed for the GNU driver).                                                                                                                                                       | Same probe; without libcpmt exactly one unresolved symbol remains.                                                                                                        |
| `/DEFAULTLIB:libcpmt.lib` alone: the `future.obj` clash returns even with libc++ 23.                                                                                            | lld-link searches default libraries in command-line order; a command-line `/DEFAULTLIB:libcpmt.lib` precedes the `libc++.lib` that arrives through object directives, so `exception_ptr`'s members resolve from `future.obj` first and then collide with `exception.cpp.obj`.                                                                                                                                                                                                                                                                                                                                                                                                                                              | Name `libc++.lib` first (previous row).                                                                                                                                                                                                                                                                 | Same probe.                                                                                                                                                               |
| Are `-gcodeview -gline-tables-only` accepted by clang-cl?                                                                                                                       | Yes (`-debug-info-kind=line-tables-only`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Used for the package's Windows objects.                                                                                                                                                                                                                                                                 | `clang-cl -### -c x.cpp -gcodeview -gline-tables-only`.                                                                                                                   |
| `pixi run` hangs for minutes on the Windows checkout.                                                                                                                           | A `pixi install` in progress holds the environment lock.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Wait or stop the install.                                                                                                                                                                                                                                                                               | `tasklist \| findstr pixi`.                                                                                                                                               |

### CI mechanics

- `gh workflow run build-llvm.yml` needs `--ref <branch>` to use the branch's script and workflow; without it the dispatch runs `main`'s.
- A new dispatch on the same branch cancels the run in progress (`concurrency: build-llvm-${{ github.ref }}`).
- `gh run view --job <id> --log` refuses while the run is still in progress; `gh api repos/clice-io/clice/actions/jobs/<id>/logs` works for a finished job of a running run.
- Configure-level validation cannot see link-time problems (`detect_mismatch`, symbols libc++ takes from the MSVC STL); a failing leg is reproduced locally with a small program linked against the freshly built `libc++.lib`, never by rebuilding LLVM.
- Baselines from the second round: a full leg (RelWithDebInfo, LTO) took 52 minutes on macOS and on the aarch64 Linux cross build, against 130–226 minutes for the old packages; archives 197 MB (aarch64 Linux) and 202 MB (x86_64 macOS) against 687 MB and 1755 MB. The plan has 2857 build steps / 2207 compiles against 5804 / 4457.
