### Pitfalls found while adapting

- `ExplicitInstantiationDecl` is added to the declaration context by Sema (`addExplicitInstantiationDecl`) and never handed to the AST consumer. `ActOnExplicitInstantiation` returns the class form's specialization (which the parser hands over) and null for the function and variable forms; those specializations reach the consumer only when a definition gets instantiated, and they sit at the pattern's location. Upstream main (May 2026) still does this. clice's `top_level_decls` and the traversal scope come from `HandleTopLevelDecl`, so at first the directives were invisible to the main-file traversal: the written template arguments of `template struct Holder<Widget>;` (stored only on the new node) lost their semantic tokens and inlay hints, and `template int zero<int>;` had no node at all. The consumer now also collects the main file's file-scope `ExplicitInstantiationDecl`s from `TranslationUnitDecl::noload_decls()` in `HandleTranslationUnit` (`noload` so a preamble's declarations stay on disk; a namespace block carries its own along), and the semantic visitor treats the node as the written directive: `RecursiveASTVisitor` traverses its qualifier, written type and template arguments, `decl_references` refers the specialization at `getNameLoc()` for the function and variable forms (the class form's name is inside its `TypeLoc`), and every specialization an explicit directive creates is an ordinary flagged instantiation subtree. That retired the class-form special cases in document symbols, inlay hints and the content table, plus `decls::is_member_specialization`; function and variable directives now get outline symbols too.
- `-fsycl-is-device` requires a GPU triple (`spirv64-unknown-unknown` is the default the driver would pick) and a `sycl_kernel_launch` function template in scope, since the compiler now synthesizes the host launch call for a `sycl_kernel_entry_point`.
- P1857R3 in the fixtures: a `module :private;` under `#if 0` is an error ("module directive lines are not allowed on lines controlled by preprocessor conditionals"), and an identifier named `module` or `import` at the start of a line is parsed as a directive; the fixtures were rewritten, not the parser.
- Completion after `T::` emits a non-callable function's parameter list as informative chunks, parentheses included; `extract_signature` opens on an informative `(`.
- Go-to-definition on `using Base::Base;` with several base constructors now lands on the first one instead of the second; the fixture documents "one of them", so the snapshot moved.
- The four `DenseMapInfo` sentinel removals and the `getTemplateParameterLists()` change were caught by the compiler; everything above only showed in the test suites.

### Pitfalls found while adapting

- A default-constructed `NestedNameSpecifier` is `Invalid`, not `Null` (`Null` is `std::nullopt`), and `Invalid` converts to `true`, so `if(!NNS)` does not guard it: `getKind()` on it hits `llvm_unreachable`. Initialize with `std::nullopt` and test the kind.
